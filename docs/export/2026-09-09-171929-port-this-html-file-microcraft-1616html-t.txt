⏺ The port is done and committed. MicroCraft now runs as pi-microcraft under the

  What was built

  The HTML's 3,900 lines of JavaScript became a pi_menu.microcraft package of
  fourteen modules, laid out like the platformer: pure Python for the world and
  rules, a Session state machine that pushes frames to a sink, and a thin Tk
  shell that holds the keyboard and runs the 20 Hz clock. Everything in the
  original carried across: the looping two-layer world generated in chunks,
  water and lava that flow and taper, fire and baked clay, grass that spreads
  and dies, the forty-minute day with time zones and the real moon's phase
  (eclipse included), particle-swarm clouds with rain, lightning and
  depth-driven waves, the physics, the inventory with splits and merges, both
  crafting grids and all recipes, buckets, the stick-lighter, item drops, and
  the twelve-shot demo tour behind the opening screen.

  Your mid-port note on the LEDs is addressed in a new palette.py. The browser
  art was too dark and too grey for the panel, so every block and item keeps its
  two-tone shape but is lifted above the LED floor and given a hue no neighbour
  shares: ore is grey with flecks of its metal, the furnace has a glowing
  mouth, clay leans blue. A test asserts every pair of blocks stays apart by a
  colour distance, and I rendered frames to PNG to check by eye.

  Deliberate deviations, all recorded in the plan document:
  - Simulations scan a 65×65 box around the player rather than full 1,250-row
    columns, which Python cannot afford.
  - Cloud particles only animate near the camera. Every cloud still drifts,
    covers and rains.
  - A fixed 20 Hz tick with three 60 Hz physics substeps, so the feel matches
    the browser.
  - Esc from the world returns to the opening screen. The HTML had no way back.
  - A --seed flag for repeatable worlds.
